# External PII training-source audit

This is a pinned source-metadata audit for prospective training expansion. It does not report model results and it did not download or inspect dataset rows. The authoritative machine-readable record is the ignored [audit manifest](../../evaluation/results/external_source_audit_20261004_v3/manifest.json), generated by [the audit CLI](../../evaluation/audit-external-pii-sources.py). It records the immutable revision, config/split, card and API metadata hashes, parquet object SHA-256, exact schema, footer row count, and unresolved checks.

The Nemotron count needs special care: the pinned Parquet footer reports 100,000 rows in the train file, while the pinned README says “50k train / 50k test.” The exact tree also contains a separate test Parquet. The manifest preserves this card/footer inconsistency; preparation should use the immutable file footer count and investigate the stale or inconsistent README statement before claiming source totals.

The evaluation adapter currently loads Nemotron's **test** split (`evaluation/privoke_eval/datasets.py`, `load_nemotron_pii`) and parses `text` plus span offsets/categories. The prospective source view above is `train`; do not reuse the test-view loader for training. Its span parser rejects malformed offsets/categories rather than treating them as clean. The Meddies loader uses config `english`, split `train`, fields `raw` and `label`, and derives positivity from non-empty category values. Parser behavior is covered by local unit fixtures, including malformed-span rejection and empty-label handling. No real source rows were parsed by this audit, so the actual Meddies `label` serialization, malformed-row rate, and distribution of empty/non-empty values remain unknown.

The pinned Meddies card declares machine-generated annotations and CC-BY-NC-4.0; avoid its `pii-bioes`, `eval`, `data`, `grpo-*`, and other derived/config views for this source scope. CC-BY-NC-4.0 is a material non-commercial restriction that must be respected. Nemotron's pinned card describes synthetic persona-grounded data with span labels and declares CC-BY-4.0. These sources provide annotated text examples; neither establishes the contextual privacy action/severity labels used elsewhere in PriVoke.

## Grouping and normalization requirements

Before combining these examples with the existing public-negative/bootstrap curriculum, load only the pinned train views and retain their source provenance. Normalize exactly as the runtime input contract does (NFC after trimming, as `privoke_eval.datasets._example` currently does), then deduplicate on normalized text across all candidate training sources. Exclude or reconcile identical text with conflicting labels; record duplicate and malformed-row counts. For Nemotron, validate UID presence, uniqueness, and UID-to-normalized-text consistency before using UID groups. For Meddies, derive a deterministic source-family key from available metadata and normalized text/template evidence, document the rule, and keep each family wholly within one partition. Metadata alone cannot certify sibling documents are independent. Partition by these source groups before fitting; then assert group and normalized-text disjointness across train, validation, and development.

This audit verified pinned card metadata, licenses, file paths/LFS SHA-256s, schemas, and row counts from bounded HTTP Range reads of Parquet footers. It did not verify row-level content, annotation quality, group independence, redistribution rights for derived artifacts, or contextual privacy behavior. The official pinned cards are [Nemotron](https://huggingface.co/datasets/nvidia/Nemotron-PII/tree/b70ffaf5ff39e079776134c5bf4381f00a9fd1ed) and [Meddies](https://huggingface.co/datasets/Meddies/meddies-pii/tree/6a5c8f5441e3b421d983c9741770262365acdd77).
