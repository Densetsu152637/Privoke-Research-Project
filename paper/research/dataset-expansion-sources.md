# Dataset expansion evidence and safe-use recommendations

**Status:** source review for a proposed training-pool expansion; no dataset rows were downloaded or parsed for this review. The locked development and final partitions were not opened. The repository's current label semantics are prompt-level presence of annotated PII, not contextual sensitivity, disclosure risk, or a recommended action. Source-level annotation absence is a valid negative only where the source documents exhaustive annotation and the row has been checked accordingly.

## Recommendation

Expand in two separately reported steps. First, use more eligible rows from the already pinned PIIMB source population to improve coverage while retaining the same source-family mix. Second, add one independently sourced training-only corpus as a distinct stratum. Do not combine scores across source strata into one headline result. Preserve source, dataset revision, original split, source row ID, document/template group, language, and annotation provenance for every row.

For the external stratum, **Meddies English** is the best clinical-coverage candidate after its pinned revision, license, exact schema, and clean-row availability are audited. Its current repository adapter reads `Meddies/meddies-pii`, config `english`, split `train`, fields `raw`, JSON-string `label`, and `id`/index group; it maps entity-valued labels to positive and uses a positive-only loader. The published paper describes synthetic clinical text and 17 languages, but that does not establish that the pinned English split contains trustworthy, exhaustively labeled negatives. Therefore, initially use it for positive-presence coverage only unless the pinned source proves exhaustive labels and clean rows; never turn absent JSON entities into negative truth without that proof. The label families and synthetic clinical origin do not supply the contextual sensitivity and visibility targets used by the original classifier.

For a separately named specificity diagnostic, **SPY** is promising because its paper distinguishes author-linked synthetic personal information from unrelated non-PII entities in medical and legal text. Its target is entity-level relevance to the authors, however, and its paper reports no train/test split. It cannot be converted directly into prompt-level clean negatives or the original contextual targets. Require document/template-grouped splitting, deterministic Faker generation, a license/access review, and label-preserving conversion before any use. It is not a substitute for clinical clean prompts.

**Nemotron-PII train** is a second candidate for broad structured/unstructured positive coverage if its exact pinned card/schema and licensing are verified. The repository's evaluator currently consumes its `test` split, so only official `train` rows can be considered, followed by source ID, group, and normalized-text overlap checks. The card's displayed split totals are inconsistent, and it does not document group-disjoint split construction; treat usable row counts and train/test independence as unknown until revision-specific verification. **AI4Privacy validation must not be reused**: it is the repository's evaluation split and derives from the same OpenPII family represented in PIIMB. AI4Privacy official train is possible only after family-level overlap checks and a license review. Do not regard a different Hugging Face dataset ID as independent provenance.

## Protected-row exclusion and split protocol

Do **not** invoke `evaluation/prepare-representation-study.py` or otherwise open `evaluation/results/locked-public/sealed-final.jsonl`. Before expanding the PIIMB pool, reproduce only the authorized *selection* procedure that created the original 1,000-row protected selection from the pinned source and seed `3102026`, using the same balanced full-scan loader and original sampler. The procedure must emit only an opaque exclusion index: keyed hashes of source ID, source group, and normalized text, plus aggregate counts and a digest. It must not write selected text, labels, categories, or scores, and it must not read either locked partition. Protect all 1,000 selected rows—not only rows assigned to one partition—so the protected split boundary is irrelevant to this exclusion step.

Then stream eligible training-candidate rows, compute the same keys, exclude any matching protected ID/group/text, resolve duplicate normalized text and ambiguous IDs, and split by document/template group. Verify zero protected-key intersections, zero train/validation group intersections, zero normalized-text intersections, class counts, and source-family counts before serialization. Keep the opaque key index outside model artifacts and evaluation reports. For external sources, record source revision and original split; screen protected PIIMB ID/group/text hashes even when the corpus is nominally independent. Hash matching cannot prove semantic independence where sources paraphrase, share templates, or strip provenance; document that residual uncertainty.

## Implementation decision gates

1. Freeze a source manifest before reading expansion candidates: exact revision, source split, license/permission, schema, annotation exhaustiveness, unit/group definition, and intended target. For this repository the immediate target is binary **annotated PII presence** only.
2. Add positive-only external data only through a training path that can represent it as positive-only, without fabricated negatives. For binary fitting, either add separately verified explicit clean examples or keep source-specific positive examples out of the binary objective until matched negatives are available.
3. For any inferred empty-span negative, establish that all in-scope PII classes are exhaustively annotated at the prompt level, then audit a stratified sample. Otherwise mark the label unavailable and exclude from binary-negative training.
4. Hold back validation groups from every source before threshold/profile selection. Preserve independent source-stratum reporting and avoid pooling source-specific rates as if they shared one sampling population.
5. Keep the locked development/final sets untouched. Any evaluation on them remains a separately authorized final evaluation after models, thresholds, datasets, and analysis are frozen.
