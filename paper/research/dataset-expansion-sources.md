# Dataset expansion evidence and safe-use recommendations

**Status:** source review for a proposed training-pool expansion; no dataset rows were downloaded or parsed for this review. The locked development and final partitions were not opened. The repository's current label semantics are prompt-level presence of annotated PII, not contextual sensitivity, disclosure risk, or a recommended action. Source-level annotation absence is a valid negative only where the source documents exhaustive annotation and the row has been checked accordingly.

## Recommendation

Prioritize official **training splits** from Nemotron-PII and Meddies English. Do not add more rows from PIIMB's benchmark test population: its card explicitly says to avoid fine-tuning on test data. Earlier PIIMB-test-derived fitting remains exploratory within-corpus evidence, not a benchmark-clean result. Report each source stratum separately and preserve source, dataset revision, original split, source row ID, document/template group, language, and annotation provenance.

Nemotron-PII is the broad structured/unstructured candidate, after exact pinned schema, license, and group audits. Its repository evaluator uses `test`, also represented in PIIMB; only its official `train` split is eligible, followed by ID/group/normalized-text overlap exclusion. Current card split totals conflict, so available row counts are unknown until exact-pin verification. Keep span annotations. Do not call an empty span list a clean negative without source-level proof of exhaustive annotation.

Meddies English is the clinical-coverage candidate. Its current repository adapter reads `Meddies/meddies-pii`, config `english`, split `train`, fields `raw`, JSON-string `label`, and `id`/index metadata; it maps entity-valued labels to positive and uses a positive-only loader. The dataset card may not expose a native row ID. If absent, a deterministic provenance-only row ID can use exact dataset revision, absolute source ordinal, and text SHA-256. Use the conservative group tuple `(document_type, document_label, text_format, edge_case)` for partition assignment; do not describe it as original document lineage without source evidence, and never use ordinal as a group. The paper *Meddies-PII: A Multilingual Framework for Personally Identifiable Information Extraction in Clinical De-identification* (arXiv:2609.12544, submitted 2026-09-11) describes nine labels; the current dataset card's seven core entity labels and nine BIOES tags are distinct representations. Plan for roughly 3,000 positive training rows and a 1,000-row group-held-out diagnostic only if pin/schema audit confirms availability; these are row targets, not group counts or observed counts. Never turn absent JSON entities into negatives without proof of exhaustive labels. These labels do not supply contextual sensitivity or visibility targets.

For a separately named specificity diagnostic, **SPY** is promising because its paper distinguishes author-linked synthetic personal information from unrelated non-PII entities in medical and legal text. Its target is entity-level relevance to the authors, however, and its paper reports no train/test split. It cannot be converted directly into prompt-level clean negatives or the original contextual targets. Require document/template-grouped splitting, deterministic Faker generation, a license/access review, and label-preserving conversion before any use. It is not a substitute for clinical clean prompts.

**AI4Privacy validation must not be reused**: it is the repository's evaluation split and derives from the same OpenPII family represented in PIIMB. Its official train is a lower-priority candidate pending family overlap and license audit. Exclude Meddies-derived MIX/BIOES views that incorporate Nemotron or AI4Privacy; use only audited core Meddies provenance. A different dataset ID does not establish independent provenance.

## Protected-row exclusion and split protocol

Do **not** invoke `evaluation/prepare-representation-study.py` or open `evaluation/results/locked-public/final.jsonl` or any other locked partition. Reproduce only the original 1,000-row protected-selection procedure from the pinned PIIMB source using the balanced full-scan loader and seed `3102026`. Emit only an opaque exclusion index: SHA-256 hashes of source ID, source group, and normalized text using distinct domain prefixes, plus aggregate counts and a digest. Never write selected text, labels, categories, or scores, and never read either locked partition. Protect all 1,000 selected rows independent of their eventual partition assignment.

Canonicalize Nemotron's 32-hex `uid` to the group key `nemotron-pii:<lowercase-uid>` used for its PIIMB parent document; PIIMB sentence IDs use `piimb:nemotron-pii:<uid>_s15`. Compare these aliases so one protected sentence protects the whole parent document. For Meddies use the conservative `(document_type, document_label, text_format, edge_case)` group tuple; do not claim original document lineage without evidence. If it has no native row ID, use exact revision, source ordinal, and text SHA-256 for a provenance-only row ID, never as a group. Exclude candidates also matching unchanged train (3,832 rows), validation (968), or bootstrap (43) keys. Keep every group in one partition; row caps may select a subset only in that group's assigned partition, and all other group rows are excluded. Hash matches do not establish semantic template independence; report that limit.

## Implementation decision gates

1. Freeze a source manifest before reading expansion candidates: exact revision, source split, license/permission, schema, annotation exhaustiveness, unit/group definition, and intended target. For this repository the immediate target is binary **annotated PII presence** only.
2. Add positive-only external data only through a training path that can represent it as positive-only, without fabricated negatives. For binary fitting, either add separately verified explicit clean examples or keep source-specific positive examples out of the binary objective until matched negatives are available.
3. For any inferred empty-span negative, establish that all in-scope PII classes are exhaustively annotated at the prompt level, then audit a stratified sample. Otherwise mark the label unavailable and exclude from binary-negative training.
4. Hold back validation groups from every source before threshold/profile selection. Preserve independent source-stratum reporting and avoid pooling source-specific rates as if they shared one sampling population.
5. Keep the locked development/final sets untouched. Any evaluation on them remains a separately authorized final evaluation after models, thresholds, datasets, and analysis are frozen.
