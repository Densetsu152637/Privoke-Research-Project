## Host, ownership and resource policy

Raw Python analysis/tests/clients run on Windows host. Existing `.venv-v1-v3-pipeline` has Python3.11.9, NumPy1.26.4, Torch2.11CPU, Transformers4.57.6, Presidio2.2.363, spaCy3.7.5 and small English3.7.1; large English is absent at planning. `.venv-fuzzer-study` provides Python3.11/NumPy for lightweight analysis. `.venv-v3-encoder` provides Torch2.12CUDA13.0; detected GPU RTX5080 has16GiB but existing3.9GiB use means ownership must be checked before new training. Docker socket access currently requires host permission. No Docker test driver or Python dataset loop is permitted. `evaluation/diagnose-semantic-calibration.py` uses container Python and is therefore not an acceptable calibration command as currently written.

Start with saved-data analysis (seconds/minutes, negligible GPU), then frozen native baseline (CPU; bound first smoke on synthetic text, never test-selected), and final/ablation inference (CPU-four-thread dedicated server; retain measured runtime rather than promise an estimate). Do not parallelize independent model servers until RAM/port ownership is confirmed. Keep ignored evidence/models under original checkout experiment/result directories; tracked records contain safe aggregate counts/hashes only. No raw prompts, vocabularies, weights or protected keys enter Git.
