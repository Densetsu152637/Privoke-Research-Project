# Analysis plan for added PII training data

## Status and research question

The pinned source audit is complete; source-row preparation, fitting, and evaluation have not yet run. This document specifies how results should be described after those steps, without implying that the planned additions improve performance. The question is whether adding positive annotated-PII examples from independent source-training splits changes the frozen sparse annotation-presence profiles on their fixed validation set and report-only source diagnostics.

The target is **binary annotated PII presence**. It is not contextual privacy risk, sensitivity, visibility, severity, category correctness, exact span recovery, or a recommended `ALLOW`/`WARN`/`BLOCK` action. A valid non-empty annotation establishes a positive row under this task. Missing, malformed, or empty annotations remain unknown unless source-level exhaustive annotation is established; the planned data loader must not silently turn them into clean negatives. Meddies labels are positive-only for this analysis, so Meddies specificity is not estimable.

## Cohort and fitting design

The prospective cap is 20,000 training rows: the existing 3,832-row training reference plus up to 13,168 Nemotron positives and up to 3,000 Meddies positives. These are targets, not observed post-filter counts. The unchanged 968-row validation set is used for the frozen threshold and `C` selection. The existing train/validation/43-row bootstrap exclusions and the opaque protected 1,000-row PIIMB selection are applied before source rows can be serialized. The locked development (502) and final (498) partitions are not read for source preparation or model selection; final remains unscored.

Assign whole source groups before selecting row caps. For Nemotron, canonicalize and validate `uid` groups. For Meddies, the four-field metadata tuple is only a conservative proxy and must not be described as true document lineage. Keep rows from a group in one partition, even when a cap leaves some rows unused. Give each row provenance including repository, revision, config/split, source ordinal/ID, annotation source, and group key. Report exclusion counts by reason and source, and prove zero source-ID, source-group, and normalized-text-key overlap across fitting, validation, and report-only source-heldout sets.

Preserve the prompt representation used by the runtime as NFC after trimming. Use the separate shared `training_text_key` for deduplication and protected-text comparison: NFKC, lowercase, normalize `[at]` and `(at)`, remove horizontal spaces between digits, and collapse whitespace. Conflicting labels for rows with the same strong key are excluded or resolved under a predeclared rule, never chosen to favor the model.

Add only verified positive whole-document examples to the existing training reference. Keep source-heldout diagnostics separate: the protocol targets 1,000 held-out rows from each added source, assigned by group before row caps; the targets may be reduced by filtering or grouping and must be reported as achieved counts. Meddies' positive-only sample can report recall, not specificity. Nemotron rows with empty spans are unknown unless exhaustive coverage is verified. Do not combine source-specific rates into one pooled external-generalization headline.

Profiles, `C` values, seeds, selection rules, and reporting strata are frozen in [the prospective protocol](../paper/research/dataset-expansion-protocol.md): three profiles, `C ∈ {1, 10}`, source-sampling seed `8102026`, held-out-group seed `9102026`, fitter seed `7102026`, and the same 20,000-row maximum. At this document checkpoint, the protocol's committed Git-blob SHA-256 is `8157a7c365f904cb6286c942aa90097bdfcbb7cc688e0e1253a6ac9c3962c9d6`; any pre-fit amendment supersedes it and must be recorded in the actual run manifest. Select on unchanged validation only, requiring recall ≥0.90, then rank eligible `C` values by balanced accuracy, specificity, recall, and lower `C`; choose threshold by the frozen specificity-at-recall-floor rule. Freeze each profile's selected model/threshold before any development inference. The source-heldout samples are report-only and do not select thresholds or `C`.

## Measures and interpretation

For validation and each source stratum, report the row count, positive and verified-negative denominators, `TP/TN/FP/FN`, recall, specificity, balanced accuracy, and group counts. Report confidence intervals with the predeclared group-aware method where sample composition supports them. Also report source-specific language/domain/document-format/category composition, prompt-length distributions, duplicate and malformed-label exclusions, and all failures. Meddies specificity is `null` because there are no verified clean examples in its positive-only scope. A missing class denominator is not zero and should not be filled by inference.

Compare each fitted profile with its matched frozen-profile control on the same 968 validation prompts using paired prediction differences and the predeclared interval method. Present the 1,000-row-per-source diagnostics separately from validation and from one another. Whole source documents and PIIMB sentence-level prompts can differ in length and style; measure this difference and stratify or qualify interpretation rather than attributing a score change solely to the new source. Reported source row counts do not establish representative clinical or deployment coverage.

Suggested methods wording once preparation confirms the plan: “We augmented the existing 3,832-row training reference with [observed count] verified positive whole-document examples from the pinned Nemotron-PII train split and [observed count] from the pinned Meddies English train split. We assigned source groups before row caps, excluded [counts by reason] using protected source, group, and text keys, and kept the unchanged 968-row validation set for model selection. The added-source diagnostics were held out by [verified grouping unit] and did not affect threshold or `C` selection.” Replace every bracketed item with archived manifest counts or omit the sentence if the gate did not pass.

Suggested results wording after actual measurements: “On the fixed validation set, the augmented [profile] changed [metric] by [measured paired difference and interval] against its matched frozen control. The separate Nemotron and Meddies held-out diagnostics contained [observed counts] and yielded [source-specific results]. These measurements concern annotated-PII presence under the stated source/grouping rules; they do not establish contextual sensitivity, privacy-policy correctness, or generalization to real clinical records.” If the experiment does not execute or the integrity gates fail, report a pre-fit limitation instead of these templates.

## Limits and confidentiality

The existing PIIMB-derived fitting reference comes from the benchmark's test population. The project protocol treats that evidence as exploratory within-corpus fitting, not a benchmark-clean training result; disclose it and do not describe the new-source result as independent PIIMB test performance. The 968-row validation set is also a fixed project selection control, not a new external test. The 502-row development and 498-row final sets remain protected; final is not scored here.

These added datasets provide annotation presence, not labels for whether an entity is private in context or what action the system should take. Synthetic persona-grounded documents and machine-generated multilingual clinical/admin text cannot establish performance on actual clinical records, user-authored prompts, privacy consequences, or action quality. The proposed labels and corpus choices need independent domain review before any contextual-risk claim.

The sparse model's token vocabulary can contain generated names, identifiers, and other source text features. Keep fitted vocabularies and all text-bearing inputs/outputs in the restricted ignored experiment area under the source licenses; do not put prompt text, entity lists, fitted vocabulary, or raw clinical content into logs, model examples, or public paper assets. Publish only reviewed count/metric summaries and the required source attribution/license information. Any stricter training-key exclusions and group records are also source material, so keep them out of public artifacts.

## Status and reporting boundary

At the time of this plan, only pinned source metadata, file identities, schemas, licenses, and footer counts are verified. Preparation eligibility counts, selected samples, fitted profiles, validation results, and source-heldout measurements are pending. The protocol and analysis make no claim that the ≥90% recall and specificity development targets are met, and these targets are not IEEE acceptance requirements. Results must be taken from immutable manifests and reports after the fit completes; no values should be inferred from source sizes or protocol targets.
